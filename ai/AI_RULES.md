# Правила работы с этим кодом — коротко, чтобы не тратить токены

## Главное

**Движок один.** Он лежит в `C:\bot\engine\src` и используется обоими ботами —
turbo и v4. Двух копий больше нет. Разбирать оба бота — пустая трата.

**Точка входа одна.** Панели запускают бота консольным скриптом
`venv/bin/passivbot`, то есть через цепочку
`setup.py (console_scripts) → passivbot_cli.main:console_main → runpy → src/main.py`.
Восстановлена с сервера 2026-10-15, поломки больше нет.

Локальная копия CLI урезана осознанно: в `CORE_COMMANDS` оставлены только
команды, чьи модули есть в сборке — `live`, `backtest` и `tool
iterative-backtester`. Остальные 56 команд (`optimize`, `downloader`,
диагностические) ссылаются на удалённые модули. **Полная таблица команд живёт
только на сервере** — `/opt/tradebot/turbo/src/passivbot_cli/main.py`
(md5 `5f1d576203e70521545de85abbb02186`). Если локальное дерево когда-нибудь
зальют на сервер, сначала верни этот файл, иначе пропадут 56 команд.

Не проверяй CLI запуском `python passivbot_cli/main.py --help` — так он не
работает по замыслу, блока `__main__` в файле нет. Правильный вызов:
`console_main()`. И не исполняй `src/main.py` — дойдёт до `asyncio.run(main())`.

**Тестов в репозитории нет** — код тестов живёт на сервере
(`/opt/tradebot/<бот>/tests`). Для локальной работы не искать, не открывать.

**Папки, которые не имеют отношения к торговле:**

| Папка | Что это | Нужна при разборе торговли |
|---|---|---|
| `telegram\` | телеграм-бот | нет |
| `extras\` | research-архив: аналитические скрипты, результаты прогонов, старые версии панелей, `extras\archive\` — историческая документация | нет |
| `ai\` | эти файлы | — |

Телеграм-бот вынесен из `v4\deploy` намеренно: он не влияет на механику
торговли. Исключение одно: `v4\deploy\sim\rehearsal.py` его импортирует
(`import telegram_bot`), в строках 54–57 папка копируется в стенд.

**Файлы не читают целиком.** `engine/src/passivbot.py` — 22 917 строк, это
примерно 250 тысяч токенов за одно чтение. Он один съедает контекстное окно.

## Порядок работы

1. **Найди символ** grep по `AI_SYMBOLS.txt`. Формат строки:
   `путь:строка<TAB>вид<TAB>имя`. Индекс свежий, перегенерация —
   `python ai/gen_symbols.py` (она же проверяет синтаксис всех файлов движка).

2. **Прочитай окно, а не файл.** Нашёл строку — читай 100–200 строк вокруг:
   `Read(path, offset, limit)`. Никогда не открывай файл целиком,
   если он больше 1000 строк.

3. **Поиск делай сам, до вопроса.** Если нужно «где обрабатывается X» —
   сначала grep, потом задача. Не проси пользователя искать за тебя.

4. **Карта проекта** — `AI_MAP.md`: состав, тяжёлые файлы, режимы панелей,
   ответы на частые вопросы («где сторона позиции», «где порог убытка»).

5. **Термины** — `AI_GLOSSARY.md`. Не переоткрывай смысл TWEL, EMA anchor,
   fill, exposure и прочего: там написано.

6. **История решений** (что уже пробовали и отвергли) —
   `engine/docs/decisions_log.md`. Прежде чем предлагать BTC-фильтры,
   coin-фильтры, смена пресетов и т.п. — проверь, не отвергнуто ли уже.

## Чего не делать

```
Анализировать и turbo, и v4                 ×2 впустую
Копаться в extras\ без явной задачи         research-архив, 150 МБ
Читать один и тот же файл дважды            помни результат
Гуглить структуру проекта                   AI_MAP.md уже есть
```

## Экономия в цифрах

| Подход | Порядка токенов |
|---|---:|
| Прочитать весь движок (~130K строк) + панели | ~2 млн |
| Работа по карте и индексу | ~30–60 тысяч |

Разница на порядок. Экономия достигается не тем, что читать меньше, а тем,
что точнее находить.

## Что имеет смысл готовить заранее

Если задача нетривиальная, проси пользователя заранее выгрузить:

- конкретный диапазон функций, а не весь модуль
- выгрузку из логов по нужной дате
- результат одного grep вместо пяти поисков

Это дешевле, чем читать код дважды.
